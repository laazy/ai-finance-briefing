### 1. Kimi K3 2.8 万亿参数权重今日正式开放：社区涌入、订阅超载暂停，自托管时代开启
- **要点**：UTC 2026-07-27 00:00（北京时间今晨 8 时），Moonshot AI 按期将 Kimi K3 完整权重发布至 HuggingFace（moonshotai 主页）。协议为修改版 MIT，允许商业部署与微调。发布后最直接的市场信号是：Moonshot 已暂停新 Kimi K3 API 订阅，因为自有服务器需求远超承载上限；随着外部机构开始自托管，服务压力有望逐步分散。模型规格：2.8 万亿参数（896 个 MoE 专家，每 token 激活 16 个），MXFP4 四位量化版约 1.4TB；最低运行门槛为 8 块 H100（80GB），完整高吞吐量部署需 64 块以上的加速器超节点。真正能本地运行的机构屈指可数，但"可部署权"本身对跨国企业尤具战略意义——自托管等同于从根本上切断数据经由中国服务器的风险链路。社区关注两大后续变量：①HuggingFace 下载量与实际部署反馈是否揭示此前未披露的幻觉率问题；②北京是否对开源模型权重出口追加管制，若如此 Kimi K3 或成最后一批可自由下载的中国前沿模型。

### 2. MCP 2.0 Release Candidate 今日 SDK Beta 全面上线，明日正式落地：最大协议重写，AI Agent 基础设施转折点
- **要点**：Model Context Protocol 官方博客今日宣布，2026-07-28 规范的四个 Tier-1 SDK 同步进入 Beta 阶段（Python v2、TypeScript v2、Go Beta、C# Beta）。明日（7/28）将正式发布最终规范。这是 MCP 自 2024 年发布以来最重大的架构变更，核心包括：**①去状态化核心**——删除 `initialize` 握手与协议级 Session，MCP Server 现可使用标准轮询负载均衡横向扩展，彻底解除此前粘性会话限制；**②Tasks 扩展重构**——`tools/call` 可返回任务句柄，由客户端通过 `tasks/get` / `tasks/update` / `tasks/cancel` 驱动异步流程，适合长时推理与多步工具链；**③MCP Apps 框架**——引入扩展注册表机制；**④正式废弃策略**——首次明确旧版本生命周期。行业影响：所有基于 MCP 的现有服务器需要迁移（部分为破坏性变更），但迁移收益显著——AI Agent 服务从单机有状态架构升级为云原生无状态架构，是将 MCP 从"本地工具中介"推进到"分布式 AI 协议"的关键一跃。

- **要点**：中国国家网络安全标准化技术委员会（TC260）于 7 月 7 日正式发出通知，向企业与科研机构公开征集"金融"与"卫生健康"两个垂直领域 AI 应用安全技术标准起草团队成员。这是 2026 年 1 月 TC260 发布通用《网络安全技术 人工智能应用安全》框架后的第一批垂直行业落地动作，采用逐行业分批推进模式。金融服务业的影响路径：一旦标准草案形成，中国境内经营的金融机构（包括使用 AI 进行信用评分、智能投顾、风控审批的机构）将需同时对齐 TC260 中国标准与 EU AI Act（8 月 2 日高风险截止）两套不同的要求体系，双重合规成本与操作摩擦将进一步上升。对 Kimi K3 等模型而言，此标准起草进程可能间接影响国内金融机构采购决策：若标准对数据本地化与模型可解释性要求严格，将利好本土模型、压制境外商业部署。
